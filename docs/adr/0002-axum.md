# 0002. Use Axum with sqlx and Postgres for the server

Status: Proposed (PLAN.md draft, 2026-10-07)

## Context

The server is a single-user API that syncs band data from the iOS app, serves the website, and receives WHOOP webhooks (PLAN.md §4.1, §12). It needs HTTP routing, middleware (timeouts, tracing, compression, auth), async database access and migrations. Alternatives were actix-web and Loco. actix-web has its own actor and runtime conventions and reuses less of the tower ecosystem. Loco adds more structure than a single-user API needs (PLAN.md §4.3).

## Decision

Use Axum 0.8.x, pinned to the released 0.8 line, because `main` is moving toward 0.9 with breaking changes. Use sqlx for async, compile-time checked queries, embedded migrations and `LISTEN/NOTIFY` (PLAN.md §4.3). Use Postgres 17 (PLAN.md §16.2).

## Consequences

- Middleware comes from `tower` and `tower-http` rather than custom code.
- `LISTEN/NOTIFY` can wake the in-process job runner, so v1 needs no Redis (PLAN.md §4.3).
- Integration tests use `#[sqlx::test]` with an isolated database per test. CI runs a `postgres:17` service container (PLAN.md §17.2).
- Moving to Axum 0.9 is a deliberate upgrade step, not an automatic one.
