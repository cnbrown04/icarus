# 0001. Use GRDB (SQLite) for on-device storage

Status: Proposed (PLAN.md draft, 2026-10-07)

## Context

The iOS app receives band data continuously. The main workload is about 86,000 or more inserts per day, batched and written from background wake-ups. Most reads are time-range queries with SQL aggregation (per-minute downsampling). The UI needs live observation of query results. The local schema must mirror the server schema for sync (PLAN.md §7.4, §10.2). SwiftData, Core Data and GRDB were compared against these criteria in PLAN.md §7.4.

## Decision

Use GRDB 7.x with `DatabasePool` in WAL mode, backed by SQLite. Observe live results with `ValueObservation`. Use the file protection `NSFileProtectionCompleteUntilFirstUserAuthentication` on the database file and directory, so background BLE writes still work while the phone is locked (PLAN.md §7.4, §18).

## Consequences

- Schema, migrations and queries are plain SQL, and map 1:1 to the Postgres tables used for sync (PLAN.md §10).
- One third-party dependency (MIT licence), so Swift 6.1 or later is required.
- SwiftData's `@Query` is not used. The app does not sync through CloudKit, so its main advantage does not apply (PLAN.md §7.4).
- Migrations are written and tested by hand, from an empty database and from each earlier version (PLAN.md §17.1).
